# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

SimpleLogin: email-alias privacy service (self-hostable). Flask backend, Postgres 13+, Redis. Python 3.12 managed with `uv`.

## Commands

```bash
uv sync                       # install deps (uses uv.lock; sl-pgp from custom find-links)
cd static && npm install      # front-end assets

# Run locally
cp example.env .env           # then edit DB_URI to your postgres
alembic upgrade head && flask dummy-data && python3 server.py   # webapp on :7777, login john@wick.com / password
python email_handler.py       # email forward/send handler (aiosmtpd)
python job_runner.py          # async jobs (GDPR export, etc.)
python cron.py                # scheduled jobs

# Tests (need Redis on :6379)
sh scripts/run-test.sh        # spins up postgres docker, migrates, runs full suite, tears down
uv run pytest -c pytest.ci.ini                          # against already-migrated DB
uv run pytest tests/test_alias_utils.py                  # single file
uv run pytest tests/test_alias_utils.py::test_name -p no:cacheprovider   # single test
# Test DB config comes from tests/test.env via CONFIG env var

# Lint / format (pre-commit runs ruff + djlint)
uv run pre-commit install
uv run ruff format .          # format python
uv run flake8                 # lint
uv run djlint --check templates   # lint jinja/html;  --reformat . to fix
```

## Database migrations

Alembic. Schema comes from migrations in production, but **local/test DBs are created via `db.create_all()`** (see `fake_data()`), NOT migrations — so models and migrations can drift; review autogenerated migrations carefully.

```bash
sh scripts/new-migration.sh   # autogenerate against a fresh docker postgres (the only correct way)
sh scripts/reset_local_db.sh  # reset dev DB to latest migration + dev data
sh scripts/reset_test_db.sh   # reset test DB to latest migration, no dev data
```

## Architecture

Two main runtime components share the same `app/` code and Postgres DB:
- **webapp** (`wsgi.py` → `server.py`): serves web UI, browser extensions, mobile apps, OAuth/"Sign in with SimpleLogin", and the API.
- **email handler** (`email_handler.py`, ~2k lines): SMTP server (aiosmtpd) implementing alias receiving (forward) and sending (reverse-alias). Core of the product.

Plus background runners: `cron.py` (scheduled, config in `crontab.yml`), `job_runner.py` (async jobs queued in DB), `event_listener.py` (proto events → partners).

### `app/` package layout (feature packages, each with `views/` blueprints)
- `models.py` (~4200 lines): **all** SQLAlchemy models + most domain logic lives here. Start here to understand any entity. Uses SQLAlchemy 1.3 + Flask 1.1 (old APIs — match existing patterns, not modern Flask/SQLAlchemy idioms).
- `config.py`: every setting loaded from env (`.env`). No setting is hardcoded elsewhere.
- `dashboard/`, `api/`, `auth/`, `oauth/`, `developer/`, `discover/`, `internal/`, `admin/`, `phone/`, `payments/`, `onboarding/`, `monitor/`: feature blueprints registered in `server.py`.
- `handler/`: email-handler subroutines (dmarc, spamd_result, unsubscribe, provider complaints).
- `*_utils.py` modules: feature logic split out of models (alias_utils, mailbox_utils, contact_utils, custom_domain_*, etc.).
- `events/`: protobuf event dispatch to partners (Proton). `app/events/generated/` is generated — do not edit (regen via `scripts/generate-proto-files.sh`).
- `email/`, `email_utils.py`, `mail_sender.py`, `message_utils.py`: email construction/parsing/sending.
- `db.py`, `extensions.py`, `session.py`: Flask/SQLAlchemy wiring, Redis-backed sessions.

### Other entry points
- `tasks/`: standalone cleanup task scripts run by cron.
- `commands/`: one-off operational/backfill scripts (run manually).
- `templates/`: jinja HTML + email templates. `static/`: assets (npm-built).
- `tests/`: mirrors `app/` package structure. No unit/integration distinction — a test just verifies a feature. `tests/example_emls/` holds raw `.eml` fixtures for email_handler tests.

## Commit & PR conventions
- Commit messages and PR text (titles, descriptions, review comments) use neutral, factual language.
- Never mention AI/Claude or any assistant. No `Co-Authored-By` trailers, no "Generated with" footers.
- Not conversational — plain imperative statements.

## Conventions
- Most logic for an entity is a method/classmethod on its model in `models.py`, or in the matching `*_utils.py`. Look there before adding new modules.
- All config via `app.config` env vars — add new settings to `config.py` and `example.env`.
- Audit logs: alias/user mutations go through `*_audit_log_utils.py` — use them, don't write audit rows directly.
- `LOCAL_FILE_UPLOAD` / S3 abstraction in `s3.py`. PGP via `pgp_utils.py` (sl-pgp native lib).

## Fork customizations
This is a fork of `simple-login/app` (`upstream` remote). Goal: add custom capability while keeping upstream merges controlled and low-conflict. Rules:
- **Isolate custom logic in fork-owned files** upstream never edits; keep upstream-file changes minimal and additive (import + call, not inline blocks). Mark fork-only files with a module docstring stating they are not upstream.
- **Prefer additive/opt-in over changing upstream contracts.** If a custom field would break an upstream test, gate it (e.g. behind a query param) so the default response stays byte-identical. Do **not** "fix" the breakage by editing the upstream test's expectation.
- Run the full suite before merging (see the test commands above).

Current fork-owned pieces (soft allow-list / "whitelist" feature):
- `app/whitelist_utils.py` — whitelist-mismatch tag generation + Subject/From insertion, extracted from `email_handler.py`. `Contact.ui_tag` in `models.py` delegates here.
- `app/api/views/alias.py` `toggle_contact` — returns the custom `ui_tag` only when called with `?ui_tag=1` (the dashboard opts in); default response is the upstream shape.
- `cleanup_whitelists.py` — fork maintenance script.
- Fork tests: `tests/test_whitelist_utils.py` (unit), `tests/api/test_contact_ui_tag.py` (opt-in endpoint). Upstream `tests/api/test_alias.py` is left unchanged.
